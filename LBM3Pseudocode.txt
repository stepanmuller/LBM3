	shift = IJKShifter[cell]
	if shift >=0:
		ukazuje na index v krátkých iArray, jArray, kArray kde přečtu polohu svojí buňky
		i = iArray[shift]
		j = jArray[shift]
		k = kArray[shift]
	else:
		Pokud je shift < 0, říká mi kolik mám odečíst ze svého indexu, abych dostal index první buňky ve spojitém řádku
		Tedy přečtu 
		firstInRow = IJKShifter[cell + shift]
		i = iArray[firstInRow] - shift
		j = jArray[firstInRow]
		k = kArray[firstInRow]

Jak vypadá updateGrid

1) Loop přes všechny buňky
	
	Read wallIndex
	if wallIndex == -2 return (= this cell itself is a wall)
	
	read compressed IJK -> iCell, jCell, kCell
	read f
	get rho, ux, uy, uz
	
	get BC
		-> fills xRotor, yRotor, zRotor (= where the cell is in frame of reference of the rotor)
		-> fills gx, gy, gz as if the rotor is present
		
	find if xRotor, yRotor, zRotor lies within rotor bounds -> I need a Rotor struct! Very clear
	The voxelization and interpolation goes like this:
	I have the finest LBM grid, inside every finest LBM cell there are 8 rotor cells
	Each rotor cell holds a value from 0 to 8. The value tells how many of the cell corners lie inside the rotor.
	I will code this into an int but also use the remaining bits to store the same information about 7 neighbour cells in the positive directions.
	This way, to get the interpolation values, all I need is to read a single int from the cell that is the closest to me in the negative directions.
	Because the rotor is going to be block-like (large blocks of zeros or ones), I will use a larger block structure to greatly save memory. 
	The large blocks will contain, lets say, 4x4x4 of those cells. If every single value there is zero, this block receives a -2. If every single value
	there is one ( or 8, just the one corresponding to full rotor everywhere ), this block receives a -1. If the values are not all the same, the block
	will receive an integer which points to a second array. The second array contains sectors of 64 ints, those are the "in detail" values.
	
	I will pack all necessary reads into 2 ints. Because the rotor is going to be block-like (large blocks of zeros or ones),
	I will use the first integer to code information about overlaping blocks.
	if it does lie within rotor bounds, read the relevant 8bit cube, calculate where we are in the cube, 
	transform that to <0, 1> on each axis, run a trilinear interpolation function that gets 3 coords and 1 uint8 as the bit packed corner values
	result is a float. 
	
	Multiply gx, gy, gz by this float. -> forcing solved!
	
	It remains to solve the walls. I need to know how much it will hinder performance if I leave additional 27 floats allocated
		-> allocating +27 floats for every thread lowered glups from 4.69 to 4.59 so this doesnt seem too problematic, 
		maybe I can really just remember fPre the whole time
	
	if wallIndex == -1 (= plain fluid)
		applyCollision(f)
		write f
	
	else if wallIndex >=0 (= wall adjacent cell)
		fPre = f
		applyCollision(f)
		&fPost = f (renaming it for later clarity)
		
		now I want to apply the wall BC -> what do I need to read?
		1) which of the neighbour cells are a wall? 
			one bit packed integer, 1 means (x,y,z) + (cx,cy,cz) is a wall
		2) for those which point to a wall, read the link distance
			I will pack the link distances into 128 bits. This can be either 4*uint32 or one 128bit CUDA vector (need to check if TNL works with this)
			Then I treat it as 4 uint32 and assign 7, 7, 7, 5 links to them. 
			Each link receives a number from 0 to 23 inclusive. I unpack the link number as following:
				for i in 7 links:
					uint32_t linkNumber[i] = value % 23u;
					value /= 23u;
